## 二、Release 必须动态发现

不要把 `v3.2.22` 或任何当前最新 Tag 写成永久来源 URL。日常测试流程：

1. 请求 `GET https://api.github.com/repos/luanmuc/legado-book-sources/releases/latest`。
2. 读取 `tag_name`、`published_at` 和 `assets[]`。
3. 从 `assets[].name` 精确查找 `books.json`、`clean_rules.json`；用返回的 `browser_download_url` 下载，不自行拼接 `/releases/download/<tag>/...`。
4. 校验 HTTP 状态、文件大小、SHA-256、JSON 是否可解析以及预期的数组/对象结构；如果资产名称变化，不静默猜测。
5. 将已验证的**测试快照**保留在开发测试缓存（不进入 APK、不自动导入用户来源库），记录 Tag、日期、哈希、下载结果和兼容性结果。
6. 对比前次快照，输出来源新增/修改/移除、`loginUrl`/`loginUi`/`header` 及脚本接口变化。
7. API 失败、限流、Release 不含必需资产、文件损坏或结构异常：报告 `BLOCKED`，不替换上一个成功快照。
8. 历史固定版本可以作为**回归测试基线**，但不可替代日常最新正式版发现。

参考 API：

```text
https://api.github.com/repos/luanmuc/legado-book-sources/releases/latest
```

**仅作为 2026-11-16 的核对示例**：当时 `v3.2.22` 具有 `books.json` 和 `clean_rules.json`；该标签不是应用常量，后续发布会变。仓库说明对“大厂正版”数量存在不同口径，因此**不要写死数量、顺序、名称**；仅使用当前 JSON 实际内容。

## 三、合法性与测试范围

- “大厂正版”只是合集作者对来源的分类；不代表网站允许第三方登录、抓取、访问 VIP 章节或分发内容。
- 默认使用本地假站点 + MockWebServer 进行登录流程、Cookie、重定向、JS 与安全测试。
- 对真实网站只在有权使用、符合服务条款且具备测试账号时验证；无需真实登录也能先分析 JSON 登录字段与规则结构。
- 不批量使用真实网站账号，不绕过验证码/风控/DRM/付费限制；测试限速、最小请求范围，不抓取或提交版权正文。
- 不把真实账号/密码、Cookie、Token、包含凭据的日志与抓包提交到仓库。

## 四、测试样本分类（从当次 JSON 中动态提取）

| 类别 | 识别特征 | 必测行为 |
|---|---|---|
| 普通来源 | 未声明登录字段 | 导入、搜索、目录、正文无回归 |
| Web 登录来源 | `loginUrl` 可确认为 HTTP(S) 页面 | 登录页、取消、Cookie 保存、会话验证 |
| 自定义登录 UI | `loginUi` 非空且符合可识别规则 | 表单控件、提交、失败提示、返回值 |
| 脚本登录来源 | `loginUrl` 为脚本/动态表达式 | 不误当网页打开、受控执行/不支持提示 |
| 登录信息 API | JS 含 `getLoginInfo[Map]`、`putLoginInfo` | 读写/删除及持久化一致性 |
| 动态 Header | 源级 `header` 或 `putLoginHeader` | 安全作用域及优先级 |
| Cookie 依赖 | CookieBridge 或认证 Cookie | 域名、Path、Secure、过期、退出 |
| WebView 动态页面 | `webView` 或 JS 渲染依赖 | WebView/OkHttp 一致性、私网保护 |
| 同域多个来源 | 多条来源指向相同或子域站点 | 账号共享声明、不可越权泄露 |
| 外部变化 | 规则新增、修改、移除 | 不删除用户本地来源与登录记录 |

### 候选“大厂来源”

## 五、兼容矩阵与结果等级

| 检查项 | 正确判据 |
|---|---|
| 导入成功 | JSON 解析并保存来源，不说明能登录 |
| 登录入口成功 | 按规则识别并显示 UI，不说明已认证 |
| 验证登录 | 有明确的状态检测证据，不能仅凭 Cookie 或 HTTP 200 |
| 会话持久化 | 重启后仍在有效会话下可进行**授权的**请求 |
| 网络集成 | 搜索、目录、正文、图片、JS、缓存入口身份正确 |
| 隔离安全 | 来源之间不混用 Cookie/Token，重定向不泄漏 |
| 普通来源回归 | 不需要登录的来源行为不变 |
| 更新回归 | 最新 Release 改变规则后不破坏用户本地数据 |

测试结果只允许：`PASS`（有证据通过）、`FAIL`（可复现失败）、`BLOCKED`（外部条件限制）、`NOT_SUPPORTED`（未实现）、`NOT_TESTED`（未执行）。不得把字段存在、构造测试或兼容推断写成 `PASS`。

## 七、自动化建议（仅开发/CI）

- CI 提供**手动触发**的“检测最新 Release”任务；可选定期元数据检查，但不要默认自动大量请求真实站点。
- 用 GitHub API 动态读取最新正式发行版；限流、网络故障应保留旧测试快照并报告。
- 下载结果只用于生成字段分布与变更报告，以及构建去敏感的最小本地夹具。
- 使用 MockWebServer 分离网络层、脚本层、WebView 层的测试；Android UI/仪器测试必须实际执行后才可报告成功。
- 不自动修改用户来源、不自动发布 APK、不自动上传/分发第三方合集。

> 核心原则：**实时发现最新发行版，固定快照复现旧问题；动态测试数据与用户生产数据严格隔离。**
