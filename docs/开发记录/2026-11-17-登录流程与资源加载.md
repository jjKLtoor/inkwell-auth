# 登录流程与网页资源加载

日期：2026-11-17。目标为单选登录入口、正常加载网页资源、保存后恢复网页，以及规则原文按需展开。只修改来源认证模块和登录/详情 UI，不改变阅读器、数据库、用户来源或更新地址。

## 最终使用流程

1. 来源详情进入「登录与会话」。首次无有效本地会话时显示入口设置；有多个可识别网页时，通过统一的 SpinnerSettingRow 单选。
2. 候选项来自规则明确声明的静态 startBrowser/startBrowserAwait 网页和有效的来源首页，不包含样式、脚本、图片、接口等依赖域名。不执行来源的登录按钮脚本；动态计算或突破既有两个 origin 认证边界的入口仍不支持。
3. 新会话默认允许公开 HTTPS 子资源，包括脚本、样式、图片、子框架和接口；保留「允许公开网页资源」开关。旧版本保存的会话按旧许可恢复，可开启一次并重新保存，不再逐个选择资源域名。
4. 新的主页面跨站跳转仍通过原生确认；可选择随会话记住精确站点，不会放行 HTTP、私网和无效证书，第三方 Cookie 仍关闭。
5. 在网站页面由用户完成登录，点击「保存会话」。保持当前网页，显示保存结果；没有有效持久 Cookie 或保存失败时不覆盖旧会话。
6. 保存所选入口、资源设置、明确记住的跳转站点及可恢复 Cookie。再次进入直接恢复并打开所选入口。入口必须仍在当前规则候选项内，否则回到当前规则的默认入口；不保存任意带临时授权参数的跳转深链。
7. 「会话」返回管理页，可切换入口或退出。退出清除该来源的加密会话和保存的网页许可。取消/返回不自动保存。

公开资源包含可执行 JS，可参与网页表单交互并使用按域名匹配的网页 Cookie，这是普通网页运行所需的权限；不宣称它只是匿名图片加载。阅读引擎继续只使用来源＋声明登录站点的精确 HTTPS origin，Header 仍限来源；资源许可不扩展引擎认证、不导出额外站点独有 Cookie。

## 实现与上游边界

- source-auth：LoginNavigationPolicy 区分主页面与子资源；LoginWebSession 的主/子窗口共用隔离 profile、域名策略和 WebViewNetworkGuard。只接受用户手势打开一个登录子窗口，展示当前站点，返回/关闭恢复父页；不自动批准弹窗、私网或第三方 Cookie。
- 网页 alert/confirm 通过 AppAlertDialog 响应，避免没有 WebChromeClient 时确认返回失败导致按钮无法继续。没有伪造浏览器标识或取消网站风控。
- CookieSession、EncryptedSessionStore、PersistentSourceSessions 保存入口和网页设置，密文格式升级 v4，兼容读取 v1/v2/v3；引擎 Cookie 轮换保留这些设置。未修改 Room 或删除旧会话。旧版 APK 不能保证读取 v4，但解密失败不会删除密文。
- SourceLoginViewModel：候选入口、选择、保存后留页及有效会话自动打开；SourceLoginScreen：共享组件、单选下拉、网页资源开关与必要的原生确认。
- SourceRulePreview：进入详情默认折叠，不排版规则；主动展开后恢复原先的完整文本、横向滚动与复制全文，没有分页。解析结果后台生成一次并供手动测试复用。超大原文主动展开时的全文排版成本仍存在，未宣称这一步零卡顿。
- 上游潜在冲突集中于来源登录页/详情展示和认证接入点，:core、:reader 本轮无业务改动，不新增散落抓取逻辑。
