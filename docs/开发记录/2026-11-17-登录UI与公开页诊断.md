# 登录 UI、受限资源与详情页性能修复

## 范围、基线与验收

基线 b11ace8，功能分支 feature/source-auth。用户要求核对更新地址、修复额外域名导致的空白、统一登录 UI，并排查来源管理进入番茄详情页的卡顿；后续要求测试全部当次大厂来源。用户明确取消外部浏览器入口和手动 Cookie 录入，本轮均未增加。

验收：受控网页在默认拦截时缺少必要内容，经原生逐站确认才恢复脚本/样式；关闭后许可失效；临时站点自己的 Cookie 不导出到阅读认证；长规则不在进入详情页时一次性排版。真实网站没有账号验证时一律不写登录成功。

## 修改与解耦

- source-auth/LoginNavigationPolicy.kt：每次交互页独立的精确 HTTPS origin 临时许可。默认范围不变，只有已观察到的拦截项可经用户原生确认允许，每次最多 8 项，关闭即清除，不写入来源配置或引擎认证作用域。
- source-auth/LoginWebSession.kt：保留 DNS/私网、TLS、第三方 Cookie、文件访问和独立 profile 防护；临时站点的 Cookie 仅留在该网页环境，capture 只导出仍符合原认证范围的 Cookie。WebView 使用真实系统 UA，避免硬编码的 Chrome/124 标识与实际内核不一致；启用手机视口、概览和缩放。
- source-auth/LoginResourceKind.kt、LoginPageEvent.kt：区分跳转、样式、脚本和图片；优先提示样式依赖，减少网页仅剩未排版 HTML 时的困惑。只保留 origin，不向诊断输出完整请求、查询参数或 Cookie。
- app/ui/sourceauth/SourceLoginScreen.kt：复用 Miuix SettingGroup/SettingRow、统一文字层级和按钮；网页使用窄顶栏、紧凑状态、底部取消/保存；受限站点有原生确认入口，403/证书错误不会被后续页面可见事件覆盖。网站内容不强行注入统一 CSS，不伪装标准浏览器。
- app/ui/sourcedetail/SourceDetailViewModel.kt：本地 JSON 后台解析一次并复用。此步骤不发网络请求；只有点击全链路测试才会搜索/抓取。
- app/ui/sourcedetail/SourceRulePreview.kt、SourceDetailScreen.kt：所有来源通用的默认折叠、约 4KB 分段排版，复制仍使用完整原文且分段不截断代理对。不硬编码番茄名称，不改转场、排版引擎、Room、书架或来源数据。
- 新增临时许可/资源分类单测、临时 Cookie 不导出设备测试、脚本/样式加载设备测试、长规则分段设备测试和仅显式参数开启的公开网页诊断测试。全部第三方快照保留在 tmp，不打包到 APK。

## Cookie 与覆盖边界

有效持久 Cookie 在 noBackupFilesDir/source-auth 中加密，密钥由 Keystore 保护；读取使用内存会话。WebView 的临时平台 profile 可能短期落盘，关闭异步清理。会话 Cookie 不作为跨进程恢复材料；不保存密码，不做无限保活。

引擎内搜索/发现/详情/目录/正文/正文图片和 JS 使用匹配的来源 Cookie；Domain/Path/Secure/Expires 和每跳 origin 仍要匹配。临时网页登录许可不扩展阅读认证。封面独立图片加载器、带认证后台 WebView 尚未完整覆盖，不能称所有 App 请求都已带 Cookie。
