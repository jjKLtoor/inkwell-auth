# 登录加载反馈、来源兼容与 Release 自测包

## 范围与验收

用户反馈所有可点击登录的来源停留在「登录中」、下方空白，部分来源提示不支持，并要求尽量适配当前大厂分组、只修改 GitHub 更新仓库、保留其余更新设置，最终交付 Release 包。用户明确授权来源＋声明登录站点两个精确 HTTPS origin 的 Cookie 适配，Header 仍只发来源。架构尽量隔离，未修改阅读器排版或页面转场。

基线 Commit：47cb704。只进行本地开发与打包，不推送、发布 Release 或合并上游。

## 已实现与文件

- source-auth/WebLoginTarget.kt：集中解析配置，缓存有界；Rhino 仅解析语法树，提取唯一静态浏览器网页声明，不执行登录脚本、按钮、Token 复制或购买逻辑。缺少登录配置时，仅为 HTTPS 来源提供明确标记的首页尝试；HTTP 登录只尝试同主机标准 HTTPS，绝不明文认证。
- source-auth/LoginConfiguration.kt、PersistentSourceSessions.kt：识别声明网页、脚本静态网页、HTTPS/首页尝试，读取双 origin 作用域；配置改域会得到不同身份，不自动迁移旧凭据。
- core/auth/SourceAuthScope 与 SourceSessionProvider：纯 JVM 最小契约；BookSourceEngine 仅向 provider 请求会话，不包含网站配置解析逻辑。HttpClient 在跳转每一跳检查 origin，认证 Header 仅发来源 origin；裸域名 Cookie API 只在当前已批准的 HTTPS origin 内补全。
- source-auth/EncryptedSessionStore.kt：v3 保留跨主机 host-only Cookie 原始主机，可读 v1/v2；旧单站作用域绑定不变，跨站新作用域不复用旧密文。
- source-auth/LoginWebSession.kt、LoginPageEvent.kt：视图附着后启动，提供加载、实际可见、HTTP/网络/证书失败及额外站点被拦截事件；仅传裁剪后的 origin，不输出查询参数。临时 localStorage 随独立 profile 清理，不导出或恢复；不放行未声明站点、私网或无效证书。
- app/ui/sourceauth/：状态卡显示确切来源/登录站点、加载/超时/错误，提供重试；视图按自己的 owner 释放，避免共享引用误关闭另一个实例；只有页面实际可见后才允许保存。表单/脚本部分支持有明确说明。
- app/update/UpdateChecker.kt：仅把 GitHub 仓库常量改为 jjKLtoor/inkwell-auth。中转服务器、稳定/测试渠道及其他设置保留。
- core/src/main/resources/META-INF/proguard/inkwell-js.pro：Rhino 依赖公开名称反射；保护规则随 core JAR 交付，避免 Release 混淆后来源桥名称丢失，不在 app 重复维护。
- 新增 Compose 登录入口设备测试、URL/脚本识别、双 origin Header 隔离、host-only 恢复、裸域名 Cookie 和最新快照解析测试。未把真实来源打包进 APK。

## 问题定位边界

本机最初的界面测试能触发请求且 WebView 高度大于零，没有复现用户设备全部空白的现象，因此不能断言原来的 LaunchedEffect 就是根因。明确发现的问题是：主文档 HTTP 错误及跨站/子资源拦截没有完整反馈；不同登录域名和脚本入口被统一拒绝，DOM 存储关闭也会影响现代登录页面。

修正后的设备测试从实际 Compose 界面点击登录，并检查「受控登录页面」内容真正可见。受控 HTTP 503 和额外站点跳转均有错误事件。真实网站是否仍有空白、Captcha/SSO 是否需要更多域名，仍需用户自行登录验证，不能由受控页面推断通过。

## 性能与上游风险

Debug 和 Release 的调试能力、R8 优化及包体不同，不能把包体缩小直接等同于页面切换帧率提高。本轮交付 Release 优化包，配置解析移到后台并缓存，但没有测得同一真实设备的切页性能数据，因此不宣称消除所有卡顿。

上游适配点集中于会话 provider、HTTP/JS 出口和 Koin，域名与配置策略在 source-auth。未修改上游页面转场、Room、书架、阅读记录或来源数据。风险是这些少量 core 适配点在上游改动时仍需回归；完整多款 WebView/真实来源/升级矩阵未完成。
