# 来源认证引擎接入与测试 APK · 2026-11-17

## 本轮目标与现状

基线 bb96dbc（feature/source-auth），上游集成基线 ef5d354。本轮开始只有网页登录预览和加密 Cookie，阅读引擎没有使用会话。本轮范围为统一引擎认证、来源隔离、页面操作优化、动态开发快照工具、设备证据和 debug APK。不合并上游，不推送或发布，不触碰用户来源、书架及阅读记录。

验收条件：引擎读取对应来源会话，重定向不泄漏，Cookie 变化可恢复，退出撤销旧会话；基线测试和 APK 生成通过。真实站点不以模拟测试推断通过。

## 修改文件与理由

- core/source/auth/SourceRequestSession.kt：纯 JVM 传输接口，协程上下文绑定来源。
- core/BookSourceEngine.kt、SourceHttpClient.kt：所有公开来源引擎入口统一绑定身份；网络每跳检查 origin，CookieJar 保留标准属性；有认证材料时禁止默认 WebView 渲染及敏感规则调试输出，最近页面缓存不复用认证请求。
- core/js/EngineJsHttp.kt、JsBridges.kt、RuleEvaluator.kt：同步/并发脚本沿用身份，登录数据进入当前来源会话；认证 Header 在网络边界注入，不跨 origin。
- source-auth/PersistentSourceSessions.kt、CookieSession.kt、EncryptedSessionStore.kt：加密 Cookie/Header 格式升级为 v2，并可读 v1；响应 Cookie 变化落盘；退出和迟到写入串行化；密钥故障保留密文并允许无凭据阅读。登录信息可能包含密码，只在内存使用。
- app/di/AppModules.kt、ui/sourceauth/ 两个文件：共享同一会话管理实例；保存、退出立即作用于引擎；Miuix 状态卡、地址和按钮，防重复保存并提供取消。入口为来源详情「登录与会话」。
- source-auth 的 JVM 与 Android 测试、tools/Test-AuthRestart.ps1：受控 HTTPS 引擎与实际 Android 页面/进程验证。
- tools/update-test-sources.mjs 与测试：动态发现 Release、状态/大小/哈希/JSON 校验、原子快照指针、字段差异和站点矩阵，失败保留缓存。
- .github/workflows/source-auth-validation.yml：手动来源检查与设备测试，尚未在远程执行。

认证存储位于 noBackupFilesDir；未新增 Room 表或迁移，未修改阅读排版、备份数据或网络保护。核心上游冲突风险集中于引擎入口、HTTP 出口、JS 桥和 Koin 这几处适配点。

SHA-256：1de203b09a9eaf24b419cdacbf42a8aa67a9ba3f79ee40a0e80f1702849ca964。

这是自测 debug 签名包，不能保证直接覆盖官方不同签名 APK；不要以清空用户数据处理安装冲突。来源由用户自行导入，未内置第三方合集。

自测顺序：来源管理→来源详情→登录与会话→登录→在网站页面自行操作→完成并保存会话→返回详情做全链路测试。会话显示未知是保守状态，保存不证明网站认证成功。

来源登录地址来自当前用户配置，没有硬编码大厂地址。更新来源需要用户主动操作；来源身份或 origin 改变不会自动迁移旧凭据。应用未新增购买/订阅功能，但不应将任意外部来源脚本视为安全；网站自动订阅设置和脚本行为需由用户确认。
