## 通用修复及边界

- 所有策略按声明字段、选项和请求行为分派，无站点名称/域名专用分支。核心仅增加 AuthenticatedPageRenderer 与会话 Cookie 快照/回写接口，仍为纯 JVM；认证 profile 逻辑在 :source-auth，:app 的现有 WebViewPageRenderer 完成接入。
- 有身份的 webView:true 取页不再静默跳过动态渲染，也不注入默认共享 CookieManager。专用 profile 串行使用，每次前后清理；失去清理完成证据后本进程拒绝继续复用。默认浏览器、交互登录 profile 和其他来源不受此清理影响。
- 隔离取页保留私网、证书、HTTPS 和精确 origin 约束。WebView 原生网络关闭，请求统一经受控客户端；域内 GET/HEAD 使用临时 profile 中匹配 Cookie，域外公网文本资源匿名获取，不复制认证 Header。服务器重定向、POST、认证 Header 和不支持的自定义请求头明确报错，不能当空结果吞掉。交互登录页仍按已有规则自动加载公网 HTTPS 资源，不新增手动域名确认。
- 选择上述路径的原因：Android 明确说明 shouldInterceptRequest 不覆盖后续重定向；不能把一次拦截误当成逐跳凭据保护。[Android WebViewClient 文档](https://developer.android.com/reference/android/webkit/WebViewClient#shouldInterceptRequest(android.webkit.WebView,%20android.webkit.WebResourceRequest))。这不是通用 Chromium 全功能接入的完成声明。
- 渲染结束仅合并实际观察 URL 下的 Cookie 更新/删除，并比较原始快照，避免覆盖并发 HTTP 刷新、用户编辑或已退出会话。平台临时 profile 在使用期间可能落盘，不宣称该临时文件被 Keystore 加密；独立加密会话仍存 noBackupFilesDir。
- Cookie 身份是名称＋域名＋路径。同一身份采集采用最后值，防止旧匿名快照覆盖新值；不同域/路径的同名项仍保留。UI 明确标注域名和路径，不按 true、0、空值猜测是否有用，也不批量删除。
- 搜索/发现列表前导减号作为顺序标记处理，旧式 JSON 链接占位符转交现有模板求值器，无磨铁专用逻辑。
- 来源管理校验通过 Koin 使用同一 BookSourceEngine/PersistentSourceSessions，并非另建无登录引擎；统一修复会进入这条调用链。但校验包含搜索/详情/目录/正文，Cookie 保存不代表这些步骤全部成功。
