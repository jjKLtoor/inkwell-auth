# 自动网页登录与 Cookie 管理

2026-11-17。本轮只简化网页登录加载流程：修复进入网页后还要选择跳转站点、旧会话资源仍被拦截的问题。未修改来源数据、书架、阅读记录、阅读器、更新地址或数据库。

## 当前行为

- 有多个可识别的规则入口时，进入网页登录前仍可通过共享下拉菜单单选一个。网页打开后按普通浏览器自动跟随公开 HTTPS 页面、移动站、登录跳转和资源，不再出现「选择登录站点」「加载网页资源」「允许公开网页资源」开关或许可弹窗。
- 当前域名继续显示在网页上方。仅不安全地址、私网、证书/网络/HTTP 错误显示明确提示，不把这些错误转成可点击的放行流程。
- 保存会话和下次自动恢复所选入口、有效 Cookie 的流程保留。没有清空用户 Cookie 或重写来源；加密文件仍为 v4，兼容旧格式。
- v4 的 webOrigins/allowWebResources 字段仅保留读写兼容，不再控制网页访问。旧会话即使保存了 false，也无需手动开启资源或重新登录来修复开关问题。新保存快照不再收集网页域名白名单。

## 边界与修改文件

- source-auth/LoginNavigationPolicy.kt：将交互页的域名审批改为 HTTPS 地址安全检查。LoginWebSession.kt 移除临时域名授权和资源开关；主/子窗口仍使用同一隔离 profile、既有网络保护、证书校验和关闭清理。
- app/SourceLoginScreen.kt：移除资源/跳转审批入口与弹窗，仅保留正常网页状态、实际域名、登录入口选择、保存和会话管理；继续复用 Miuix 主题组件。
- CookieSession.kt 标注旧字段的兼容用途；EncryptedSessionStore 的格式与加密没有变化。未改 Room，也不主动重写现有密文。
- 阅读引擎仍只按原来源＋声明登录站点的两个精确 HTTPS origin 和 Cookie 的 Domain/Path/Secure/Expires 规则发送身份；Header 仍限来源。网页能打开额外站点不代表它的独有 Cookie 会被导出或授予引擎使用。
- 网页 JS 与跳转按普通网页运行，可能使用按域名匹配的网页 Cookie；不宣称匿名浏览。第三方 Cookie、Service Worker 网络、无效证书和私网防护保持既有行为。
- 上游冲突集中于认证模块和登录页，不新增散落抓取适配或修改阅读逻辑。真实账号登录、所有网站 403、第三方 Cookie / localStorage 认证恢复仍未验证。

## 验收

本地受控网页验证一次点击登录后脚本、CSS、多域资源和移动登录跳转自动加载，不出现任何域名批准按钮、不因批准重载；旧会话 false 设置也可显示内容。认证模块验证跨站网页可见但其独有 Cookie 不导出，私网跳转仍拦截。测试结果、命令、APK 哈希与签名完成后续记。

本轮不访问真实账号、不触发购买、不抓取正文、不更新或导入第三方来源，不推送远程、不发布 Release。

## 已保存 Cookie 管理

按本轮用户新增要求，加入「会话 → 已保存 Cookie」。默认掩码显示，用户点显示值后才展示，并可选中复制；不自动写剪贴板。逐条编辑值或删除，域名、路径、Secure、HttpOnly、host-only 和有效期保留原属性，不提供整段请求头导入或跨域修改。凭据只在本页内存使用，不用 rememberSaveable，不记录到日志。

- SourceCookieScreen.kt 沿用 AppScaffold、AppTopBar、SettingGroup、AppFormField、AppAlertDialog、主题文字与 Dimens，长列表按需布局，操作随大字号可换行。
- SourceLoginViewModel 读取/刷新、编辑和删除结果不把 Cookie 存在判为已登录，错误不回显凭据。
- PersistentSourceSessions 在统一会话边界编辑；校验 Cookie 值与过期/变化的快照，冻结旧会话后原子写入，迟到响应不能复活旧值。写入失败恢复原内存快照并保留旧密文；只落盘持久 Cookie 与允许的认证 Header，不将内存登录信息/密码持久化。
- 修改后引擎下一次读取使用新会话；删除最后一条只清理当前已保存认证材料，其他来源和用户数据不动。Cookie 值格式错误或服务器拒绝时仍可能需要重新登录。
