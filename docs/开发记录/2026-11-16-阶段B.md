## 安全与兼容性边界

1. 自有会话文件位于 `noBackupFilesDir/source-auth/`，AES-256/GCM 密钥由独立 Android Keystore alias 保护；AAD 绑定来源 ID 与规范化 origin。文件名只含摘要，磁盘临时文件也是密文；失败不回退明文。
2. 登录只支持已识别的同 origin HTTPS 页面。UI 不接收密码，不执行 loginUrl 脚本，不提供自定义表单；localStorage、跨站 SSO、第三方与分区 Cookie 暂不支持。
3. 独立随机 WebView profile 不使用默认 CookieManager；禁用文件、content、混合内容、第三方 Cookie、Service Worker 网络及网页持久化 DOM 存储。复用 App 的 WebViewNetworkGuard。
4. 要求平台同时支持 MULTI_PROFILE / GET_COOKIE_INFO / DELETE_BROWSING_DATA；缺少能力时拒绝开启预览，不降级为共享 CookieManager。
5. Chromium `getCookieInfo` 为 host-only Cookie 也添加 domain 属性，不能直接作为 Set-Cookie 解析。专门转换恢复 host-only，保留 Domain / Path / Secure / Expires / HttpOnly；分区 Cookie 不降级为普通 Cookie。
6. 只保存已访问 URL 可见且有有效到期时间的 Cookie。session Cookie 不跨进程保存；未采集到可恢复 Cookie 不覆盖旧会话。取消不调用保存；过期只改变会话提示，不删除来源、书架或阅读进度。
7. 默认显示「会话已保存，登录状态未知」，没有自动 VERIFIED 推断。HTTP 200、Cookie、页面完成不能证明账号已登录。
8. WebView 原生 profile 在交互期间可能自行落盘，**不属于自有 Keystore 加密格式**。关闭时先销毁视图，等待该 profile 的全部浏览数据清理；已加载 profile 本进程无法删除，只能在下一进程进入会话页时删除空 profile / 异常残留。不能承诺物理安全擦除；该原生目录不备份、不导出。
9. WebViewNetworkGuard 仍有上游已记录的 DNS 重绑定限制，WebView 子资源重定向拦截也不能等价于接管每一跳连接。未承诺完整多来源独立账号；当前只支持一次交互登录。
10. `SessionCookieJar` 仅为阶段 B 的受控客户端适配：每次 Cookie 请求匹配要求完整 origin 与 Cookie.matches，跨端口 / 域名不发送。尚未替换阅读引擎的共享内存 CookieJar，界面明确提示此限制。

## 测试记录与发现

- 最新测试来源 API：实际请求 `releases/latest` 返回 HTTP 403；没有取得 Tag / published_at / 资产哈希，无已验证快照可回退，不猜测版本、不覆盖缓存。

- 核查 Chromium 官方实现与单测，发现完整 Cookie 属性行的 host-only 编码差异；加入专用转换与两项回归测试。
- 初次 Android 设备执行：Keystore 1 项通过；profile 测试暴露 `Cannot delete in-use profile`。修复为异步 `WebStorageCompat.deleteBrowsingData`，等待回调后才报告清理完成；不把 destroy 等同于数据删除。
- Android 35 镜像自带旧 WebView 缺少安全清理能力：修复后 Keystore 通过，profile 测试按能力检测跳过，**不能标为 profile 测试通过**。
