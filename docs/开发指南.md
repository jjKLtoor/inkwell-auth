## 1. 目标与非目标

### 1.1 目标

1. 对用户自行导入的 Legado 兼容来源，识别 `loginUrl`、`loginUi` 等登录配置并提供登录入口。
2. 用户用 WebView 完成网站允许的交互式登录；按规则兼容必要的自定义登录表单和脚本登录信息。
3. 本地安全保存 Cookie、规则登录信息和认证请求头；重启应用后恢复**仍有效**的登录会话。
4. 原有搜索、发现、详情、目录、正文、图片、缓存及 JS 请求，在**确有合法授权、技术可兼容**时使用对应认证信息。
5. 未登录来源维持现有行为，登录失败时不损坏来源、书架或阅读进度。
6. 认证代码相对独立，能持续合并 Inkwell 上游版本。

### 1.2 非目标

- 不开发起点/番茄等专用客户端，不解析/规避其非公开授权与安全机制。
- 不内置来源、账号、付费正文或第三方 API；不收集用户密码到开发者服务端。
- 不承诺每个 Legado 来源都能登录；不承诺 VIP 正文可阅读。
- 不为兼容来源取消 HTTPS 校验、内网防护、脚本沙箱或其他安全保护。
- 不把测试合集自动同步到最终用户的来源库。

## 3. 模块化架构设计

### 3.1 推荐依赖方向 [拟新增]

```text
                      :app
                   /    |    \
         :source-auth  :core  :reader
               |
               +-----> :core (仅使用稳定纯 JVM 契约)

:core 不依赖 :source-auth；:reader 无认证依赖
```

- `:core`：定义平台无关的认证读取、请求作用域及会话通知接口；不引用 Android 类。
- `:source-auth`：Android Library，提供 WebView 登录协调、Cookie 桥接、持久化、安全存储和状态机。
- `:app`：通过 Koin 注入、接入来源页面，负责生命周期和 UI。
- 若抽象使简单扩展变复杂，可在代码审查后缩减模块范围，但不得复制整套来源引擎。

### 3.2 稳定接口（设计草案，不是已有代码）

```kotlin
// 建议放在 :core，具体 suspend 语义应先核对调用链
interface SourceAuthContext {
    suspend fun requestHeaders(sourceId: String, requestUrl: String): Map<String, String>
    suspend fun loginInfo(sourceId: String): String?
    suspend fun loginHeader(sourceId: String): String?
}

enum class AuthStatus {
    NOT_CONFIGURED, LOGGED_OUT, AUTHENTICATING,
    VERIFIED, EXPIRED, UNKNOWN, ERROR
}
```

实施前先做架构评审：`SourceHttpClient` 和 Rhino 脚本可能存在同步路径，**不得在 UI 线程使用 `runBlocking` 读取加密存储**。可在 App 初始化时异步恢复只读内存快照，再通过线程安全更新机制同步至 JS 桥。注销/失效必须即时清理该快照。认证请求如无法明确身份上下文，不应猜测身份发送凭据。

### 3.3 最小上游修改范围

1. `settings.gradle.kts` 注册 `:source-auth`；`app/build.gradle.kts` 增加模块依赖。
2. `:app` 中的 Koin 配置及来源页面增加集成入口。
3. `:core` 的 HTTP / Engine / JS 桥仅增加**统一适配点**（最终修改文件以实际检查为准）。
4. 避免把 Cookie 逻辑复制到搜索、详情、目录、正文、图片每条业务路径。
5. 维护 `docs/上游适配清单`（可在开发指南附录或独立文件）说明每个改动及上游冲突风险。

## 4. 登录配置与能力识别

### 4.1 登录类型

| 类型 | 识别与处理 | 初期优先级 |
|---|---|---|
| HTTP(S) 网页登录 | 仅经过安全解析的绝对/可解析相对 URL 交给 WebView | P0 |
| `loginUi` 自定义表单 | 对照可验证的 Legado 规则语义，解析支持的控件并明确提示不兼容项 | P1 |
| JS `loginUrl` | 可能是可调用脚本、工具函数或动态 URL，不能直接作为网页地址 | P1 |
| `getLoginInfo[Map]` / `putLoginHeader` | 现有桥接语义基础上做持久化连接 | P0 |
| 登录校验脚本 | `loginCheckJs` 等字段**需先核实来源格式及实现语义** | P1 |

### 4.2 兼容性原则

- 保留来源原始 JSON；未知字段不得静默丢弃为错误的登录规则。
- 登录配置可用性与来源本身能否搜索/阅读分别判断。
- 优先兼容实际下载到的来源规则，而非一次性实现完整 Legado 规则集。
- 特殊认证流程（如设备校验、专有协议、DRM、App 专用签名）未获得授权时不实现绕过。
- 对规则 JS 读取敏感登录数据应设置信任边界与用户警告；来源脚本视作不可信代码。

## 5. UI 与操作流程

### 5.1 页面入口

在「设置 → 来源与净化 → 来源管理」中对有登录配置的来源展示：

- 登录 / 重新登录。
- 退出登录。
- 登录状态与必要错误原因（不暴露敏感信息）。

符合 `CLAUDE.md` 的 Miuix 主题、导航、语义色、控件复用、返回规则。用户界面统一使用「来源」。

### 5.2 正常网页登录

```text
用户选择来源 → 检查登录配置和目标站点 → 打开交互 WebView
→ 用户手动完成网站登录（含正常验证码/扫码）
→ 仅采集网站允许且确有必要的会话信息
→ 安全存储 → 按有证据的校验结果更新状态
→ 后续授权请求使用对应凭据
```

- WebView 必须在主线程操作；页面退出销毁不再使用的实例，避免泄漏。
- 复用 `WebViewNetworkGuard` 等现有安全策略，不取消内网访问限制。
- 确认目标 URL 的 scheme、host、跳转与跨站访问；拒绝危险协议或意外跳转。
- 无法验证的场景显示 `UNKNOWN`，**不因 Cookie 存在、网页加载完成或 HTTP 200 就显示登录成功**。
- 用户取消时清理临时登录状态，不应误删除先前有效会话，除非明确选择退出。

### 5.3 状态机

`NOT_CONFIGURED / LOGGED_OUT / AUTHENTICATING / VERIFIED / EXPIRED / UNKNOWN / ERROR`。

提示文案应区分：配置缺失、网站不可达、登录取消、校验不确定、会话过期、技术暂不支持和第三方服务限制。不以所有 403/429 响应直接推断 Cookie 失效。

## 6. Cookie、请求头与持久化

### 6.1 数据结构（逻辑模型，非现有表）

| 属性 | 用途 |
|---|---|
| `sourceId` | Inkwell 来源身份；来源变更时校验映射 |
| `authProfileId` | 认证上下文 ID，预留同站多身份扩展 |
| `origin` / `allowedHosts` | 登录站点及允许发送身份信息的范围 |
| `cookieRecords` | 具备 Domain/Path/Secure/Expires/host-only 等信息的 Cookie |
| `loginInfo` | 规则 JS 所需登录字段（敏感） |
| `loginHeader` | 规则 JS 所需认证请求头（敏感） |
| `lastVerifiedAt` / `updatedAt` | 状态校验与变更时间 |
| `state` | 上述认证状态 |

不把 Cookie 简化为一个全站通用字符串，以免破坏路径/子域/安全属性。**Cookie 默认由服务端 Set-Cookie 和合规 CookieJar 处理，不要把响应头粗暴用分号切分后当作通用 Cookie 持久化格式**；现有 `setCookie` 是规则兼容入口，不能替代完整的持久化方案。

### 6.2 加密存储

1. 使用 Android Keystore 保护本地加密密钥，选择维护中的加密实现。
2. 仅存必要的会话数据；用户密码原则上由网页自身处理，不另行存储。
3. 禁止把认证数据写入来源 JSON、普通 Room 字段、WebDAV `backup.json.gz`、日志、调试导出、崩溃报告或 Git。
4. 处理恢复失败、密钥不可用、进程被杀、应用升级和 Android 自动备份/恢复场景，不得出现明文降级。
5. 来源规则删除时明确清理策略，退出登录时清理登录信息及可归属的 Cookie，但不删除书架或阅读进度。

### 6.3 WebView 与 OkHttp 的关系

- `android.webkit.CookieManager` 通常按 WebView 数据目录维护 Cookie，不按 `sourceId` 天然隔离；多个 WebView 并不意味着多账号隔离。
- `SourceHttpClient` 现有 `MemoryCookieJar` 共享时必须审查跨来源污染风险。优先设计明确定义的 `AuthContext` 或 CookieJar 适配，保证请求来源身份清晰；若无法确保隔离，不支持并发多账号。
- `HttpOnly`、localStorage、第三方 Cookie、不同子域的会话不会自动一比一映射至 OkHttp；必须逐项验证。不实现偷偷读取浏览器受保护存储的行为。
- 通过 `CookieManager.flush()` 等平台机制协调 WebView 持久化，但不能把它等同于 App 自定义认证存储。
- 登录后只在目标域名符合安全规则时发送凭据。跨域跳转不得泄露 Authorization / Cookie 等敏感头。
- 不关闭 TLS 校验，不允许授权字段突破既有网络/脚本安全防护。

### 6.4 请求覆盖矩阵

| 请求入口 | 需要检查的认证路径 |
|---|---|
| 搜索、发现 | 静态 Header、动态 Header、Cookie |
| 书籍详情、目录、正文 | 来源脚本 Header 与认证上下文 |
| 图片、预加载、缓存、更新 | 和阅读请求一致的来源身份 |
| `java.get`、`java.post`、`java.ajax`、`java.connect` | Rhino → EngineJsHttp → SourceHttpClient |
| WebView 渲染/交互 | CookieManager、网络限制、站点导航 |
| 规则自行设置 Cookie | CookieBridge 的受限读写语义 |

优先在统一出口添加认证，回归测试确认所有路径正常，避免某个 HTTP 方法遗漏 Cookie。

## 7. 退出、过期与数据清理

- 退出登录：撤销本地会话、规则登录信息、相关运行时缓存、可安全归属的 Cookie；共享网站身份需提示可能影响其他来源。
- 登录失效：只影响认证相关操作，不损坏用户来源和阅读记录；不无限重试，也不自动绕过验证码。
- 用户更新来源：若 `sourceId`、登录域名或身份范围改变，须重新评估旧凭据能否复用；**默认不迁移凭据至未知新域名**。
- 清理缓存：普通正文缓存清理不等同于退出登录。
- WebDAV：默认不包含第三方认证数据；必要的凭据迁移应单独设计并征得用户同意。

## 10. 构建、Git 与发布

### 10.1 测试基线

```bash
./gradlew :core:test :reader:test :app:testDebugUnitTest
./gradlew assembleDebug
```

新增 `:source-auth` 后再根据它的 Android Gradle Plugin 配置运行模块单测和 `connectedDebugAndroidTest`（或项目实际提供的任务），先用 `./gradlew tasks` 核实任务是否存在。WebView 行为必须经过 Android 环境验证。

### 10.2 Git

```bash
# 检查后再添加 upstream（已存在则不要重复添加）
git remote -v
git remote add upstream https://github.com/radiumCN/inkwell.git

git fetch upstream
git switch main
git merge upstream/main

git switch feature/source-auth
git merge main
```

如果功能分支尚不存在，从 `main` 创建；功能稳定后经过测试再 PR 合并自己的 `main`。**禁止以 `git reset --hard upstream/main` 代替合并自定义改动。** 与官方签名不同的自编译 APK 可能无法直接覆盖安装官方 APK，需明确迁移和备份方案。

## 11. 最终验收表

| 检查项 | 必须达到 |
|---|---|
| 普通来源 | 原有搜索/目录/正文功能回归通过 |
| 网页登录 | 合规交互、可取消、可退出 |
| 持久化 | 应用重启后有效会话恢复、无明文泄露 |
| JS 兼容 | `SourceBridge` 的登录读写行为有单测 |
| Cookie | Domain/Path/Secure/过期/跨来源/重定向测试通过 |
| 来源数据 | 最新 Release 动态发现，失败回退到已验证快照 |
| 用户数据 | 更新/清理/退出不删除书架或阅读进度 |
| 上游同步 | 编译及关键回归通过，改动点可审计 |
| 合规 | 不内置来源/破解能力；真实站点访问有明确使用条件 |
